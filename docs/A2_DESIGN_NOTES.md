# A2 設計メモ（ゲートの前の下調べ）：凝縮の温度と、生成が崩れる温度

状態：**下調べのメモ（ゲートではない）**。2026-10-27（Claude）。オーナーの決定「案イ（A2 に集中）」（19:51、`LOGIC_MAP.md` §5）を受けて書いた。ゲートは明日以降、オーナーの散歩のあとに書く。

## 1. 全体をつなぐ考え方（v2 の地図から）

段 0（恒等式）を段 1（モデルが学んだ形）に当てると、**一歩ごとの分布についての予言**が出る。生成した文章は、一歩ごとの分布が前の出力を入力にして積み重なったもの（フィードバックがある）。だから、

> **一歩の予言と、文全体の実際のふるまいの差 ＝ フィードバックの量**

を測るのが、恒等式の罠にかからない本当の問いになる。候補B（繰り返しの増幅率）、候補C（κ の差）、A2（崩れる温度）は、どれもこの形にできる。

## 2. A2 の問い（対立の形）

生成が崩れる温度 T_c は、

- **(i) 一歩の凝縮の温度 T\*（a と h で決まる）と同じくらい**か、
- **(ii) T\* より低い**（フィードバックで早めに崩れる）か、
- **(iii) モデルによらず 1 くらい**か。

T\* の候補（どれを本命にするかはゲートで決める）：

- **T_half**：順位 100 以降の確率の合計が半分を超える温度。a と頭の強さ h の両方で決まる（レビュー役と Claude の計算：純粋なべき a = 1.4 で 1.33、1 位を +5 で 1.65、+10 で 2.07）。
- T_on_tail（＝ 壁のまわりの局所の傾き、A1 で測った）。
- 一歩の比熱のピークの温度 T_C（A1：Qwen の 2 モデルで中央値 1.95・1.72）。

**まだ、どの本物のデータでも T_half は計算していない**（予想の前に計算しないため）。

## 3. 先行研究の臨界温度（分布の外のデータとして使える）

| 研究 | モデル | 崩れる温度 | 決め方 |
|---|---|---|---|
| Nakaishi ほか（arXiv 2406.05335） | Pythia 160M（付録で 410M〜2.8B、ほかの言語も） | **T_c ≈ 1**（160M）。ほかの大きさも同じような転移だが、値は書いていない | 相関の積分 τ が文の長さ N とともに伸びるか（T ≲ 1 で伸びる、T ≳ 1 で頭打ち）。T = 1 で相関はべきで減る（指数 ≈ 0.2）。低温では周波数のピークの数が N とともに増える |
| Sun ほか（arXiv 2501.16241） | Qwen2.5 の 0.5B〜32B、Math、Coder | **T_c ≈ 1.2**、大きさによらず同じ | トークンのベクトルどうしの内積の和を長さで割った「エネルギー」 |
| Arnold ほか（arXiv 2405.17088） | Pythia 70M、プロンプト 1 つ | T₁\* ≈ 0.02（凍った相→まともな相）、**T₂\* ≈ 0.5**（まともな相→でたらめ。転移ではなく移り変わりかも） | 出力の分布の統計的な距離。比熱は補助。**プロンプトで大きく変わる**と明記 |

注意：決め方が 3 つとも違う。値をそのまま比べるのではなく、**順番**（どのモデルが高いか）と **大きさによるかどうか** で比べるのが安全。

## 4. いちばん安い最初の一歩（A2-1 案）：文献の T_c と、一歩の T\* を比べる

生成はしない。logit を取って T\* を計算し、文献の T_c と並べる。

- **Pythia 70M・160M・410M・1B**：PROJECT_A が Dropbox の `/stash/PYGROW/` に残した logit（最後のチェックポイント step143000 を含む 4 つのステップ、自分で書いた続き）が使える。GPU いらず。おまけに学習の途中（step 0・512・8000）の T\* の変化も見られる。
  - 注意：70M・160M は「いつも沈んでいる 324 個の ID」がいちばん下にある（PROJECT_A `EXPLORE_SHAPE_SUNK.md`）。順位 100〜10,000 には入らないが、σ などには効く。
- **Qwen2.5 の素のモデル（0.5B・1.5B・3B・7B、できれば Math・Coder）**：Sun らと同じ家族。logit を取る必要あり（小さい GPU の回）。A1 の PQW7・PQC7 は指示調整したモデルなので、Sun らのモデルと同じかは要確認。
- 予言の形（案）：
  - **順番**：Pythia 70M（文献 ≈ 0.5）＜ Pythia 160M（≈ 1）＜ Qwen2.5（≈ 1.2）の順に T\* も並ぶか。
  - **大きさ**：Qwen2.5 の 0.5B〜7B で T\* がそろうか（Sun らは T_c が大きさによらないと報告）。
  - **(i)(ii)(iii) のどれか**：T\* が T_c と同じくらいか、T_c より高い（＝フィードバックで早く崩れる）か。
- 弱いところ：文献ごとに崩れの決め方とプロンプトが違う。70M は 1 プロンプトだけ。だから A2-1 は「当たりをつける」段で、本番は A2-2。

## 5. 本番（A2-2 案）：同じ物差しで生成して崩れる温度を測る

- a と h がはっきり違うモデルを 4〜5 個（A2-1 で T\* の幅を見てから選ぶ。Pythia の学習途中のチェックポイントは、同じ作りで a だけ違うモデルとして使えるかもしれない）。
- 崩れの定義は**生成の前に固定**する。候補：
  - Nakaishi 型（相関の積分が文の長さとともに伸びるか。長さで境目が鋭くなるかも同時に見られる＝「相」と呼べるかの確かめにもなる）。
  - Arnold 型の比熱（文全体のエネルギー −log p(T=1) の温度による変化の山）。
  - Taylor の指数（人の文章 0.58、理想気体 0.5）。
- 予言は (i)(ii)(iii) の対立で書く。
